# Desktop Reporting & Professional View

> มุมมองเดสก์ท็อปสำหรับงานบัญชี / รายงานการเงิน / เบิกงบ  
> ใช้ข้อมูลชุดเดียวกับมือถือ แต่แสดงแบบละเอียดและหลากหลายมุมมอง

---

## 1. วัตถุประสงค์

นอกจากการบันทึกส่วนตัวบนมือถือแล้ว ระบบควรรองรับการใช้เพื่อการทำงาน เช่น:

- ทำสรุปค่าใช้จ่ายส่งบริษัทเพื่อเบิกงบ
- ดูรายการละเอียดทุก transaction
- สร้างรายงานรายวัน / สัปดาห์ / เดือน / ปี
- ให้นักบัญชีหรือผู้รับผิดชอบการเงินตรวจสอบได้ง่าย
- มีแดชบอร์ดหลายมุมมองบนหน้าจอใหญ่

**หลักการ:** ข้อมูลชุดเดียว (มือถือ + เดสก์ท็อป)  
มือถือ = บันทึกเร็ว  
เดสก์ท็อป = วิเคราะห์และรายงานละเอียด

---

## 2. กลุ่มผู้ใช้ของมุมมองนี้

| กลุ่ม | ความต้องการหลัก |
|------|----------------|
| พนักงานทั่วไป | สรุปค่าใช้จ่ายส่วนตัวเพื่อเบิกงบ |
| ฟรีแลนซ์ / เจ้าของกิจการเล็ก | ดูรายรับ-รายจ่าย + ส่งรายงานลูกค้า/บัญชี |
| นักบัญชี / ผู้ช่วยบัญชี | ตรวจรายการละเอียด, กรอง, ส่งออก |
| ผู้จัดการ / หัวหน้า | ดูภาพรวมและอนุมัติเบิก |

## 3. ฟีเจอร์หลักของ Desktop View

### 3.1 แดชบอร์ดหลายมุมมอง

| มุมมอง | การใช้งาน |
|--------|----------|
| **Calendar** | ดูรายการตามวัน บนปฏิทินเดือน/สัปดาห์ |
| **Grid (ตาราง)** | ตาราง transaction แบบ spreadsheet แก้ไข/กรองได้ |
| **List** | รายการเรียงตามเวลา ละเอียดทุกฟิลด์ |
| **Summary Cards** | การ์ดสรุปตัวเลขด้านบน (รายรับ, รายจ่าย, สุทธิ, รอเบิก) |
| **Charts** | กราฟสัดส่วนหมวดหมู่, แนวโน้มรายเดือน (ขยายทีหลัง) |

### 3.2 รายละเอียดทุก Transaction

แต่ละรายการแสดงได้ครบ เช่น:

- วันที่ / เวลา
- ประเภท (รายรับ / รายจ่าย / โอน)
- จำนวนเงิน
- บัญชีที่เกี่ยวข้อง
- หมวดหมู่
- รายละเอียด / หมายเหตุ
- ผู้บันทึก (กรณีบัญชีร่วม)
- สถานะ (ส่วนตัว / สำหรับเบิก / เบิกแล้ว)
- ไฟล์แนบ (ใบเสร็จ) — ขยายทีหลัง
- ลิงก์ไปยัง Goal (ถ้ามี)

### 3.3 การกรองและค้นหาขั้นสูง

- ช่วงวันที่ (วัน / สัปดาห์ / เดือน / ปี / กำหนดเอง)
- ประเภทบัญชี (เงินสด, ธนาคาร, บัตรเครดิต…)
- หมวดหมู่
- ประเภทธุรกรรม
- สถานะเบิกงบ
- ผู้บันทึก
- ค้นหาข้อความในชื่อ/หมายเหตุ

### 3.4 การส่งออกและรายงาน

- ส่งออก CSV / Excel
- ส่งออก PDF สรุปสำหรับเบิกงบ
- เลือกรายการที่ต้องการใส่ในรายงาน
- แม่แบบรายงานเบิกงบ (หัวข้อ, ช่วงวันที่, รวมยอด, ลายเซ็น)

### 3.5 สถานะสำหรับงานเบิกงบ (แนะนำเพิ่ม)

เพิ่มฟิลด์ใน transaction เพื่อรองรับงาน:

```text
reimbursement_status:
  - none          → ส่วนตัว ไม่เบิก
  - pending       → รอเบิก / รอส่ง
  - submitted     → ส่งให้บริษัทแล้ว
  - approved      → อนุมัติแล้ว
  - rejected      → ไม่อนุมัติ
  - paid          → ได้รับเงินแล้ว
```

## 5. มุมมองแต่ละแบบโดยละเอียด

### 5.1 มุมมองปฏิทิน (Calendar)
- คล้ายมือถือ แต่ใช้พื้นที่กว้างกว่า
- แสดงยอดรวมต่อวัน + วันหยุด / วันลา / นัดหมาย
- **คลิกวัน** → เปิดแผงด้านข้าง: อัปเดตเป้าหมาย, บันทึกนัดหมาย, สร้างวันลา
- **Multi-select หลายวัน** → สร้างอีเวนต์หรือวันลาทั้งช่วงได้
- **สร้างจดหมายลางาน** จากวันที่เลือก พร้อมบันทึกวันลาลงระบบ
- ไฮไลต์วันที่มีรายการรอเบิก / มี overlap

### 5.2 มุมมองตาราง (Grid)
- เหมือน spreadsheet
- คอลัมน์: วันที่, ประเภท, รายละเอียด, หมวด, บัญชี, จำนวน, สถานะเบิก, ผู้บันทึก
- เรียงคอลัมน์ได้, กรองในคอลัมน์ได้
- แก้ไข inline ได้บางฟิลด์ (หมวด, สถานะเบิก, หมายเหตุ)
- เลือกหลายแถวเพื่อเปลี่ยนสถานะหรือส่งออกพร้อมกัน

### 5.3 มุมมองลิสต์ (List)
- รายการละเอียดทีละแถว
- แสดงหมายเหตุและข้อมูลเพิ่มได้เต็มที่
- เหมาะกับการไล่เช็ครายการทีละรายการ

### 5.4 แดชบอร์ดสรุป
- การ์ดตัวเลขสำคัญ
- กราฟวงกลมสัดส่วนหมวดหมู่
- กราฟแท่งรายรับ-รายจ่ายรายเดือน
- รายการล่าสุด / รายการรอเบิก

## 6. การขยายฐานข้อมูลเล็กน้อย (เพื่อรองรับงานเบิก)

เพิ่มในตาราง `transactions`:

```sql
-- ฟิลด์เพิ่มสำหรับงานเบิกงบ / รายงาน
reimbursement_status  TEXT DEFAULT 'none',
-- none | pending | submitted | approved | rejected | paid

reimbursement_note    TEXT,                -- หมายเหตุสำหรับบัญชี
receipt_url           TEXT,                -- ลิงก์ใบเสร็จ (ถ้ามี)
project_code          TEXT,                -- รหัสโปรเจกต์ / แผนก (ถ้ามี)
is_billable           BOOLEAN DEFAULT false
```

ไม่จำเป็นต้องมีตารางใหม่ทันที ใช้ฟิลด์เพิ่มใน `transactions` ก็เพียงพอสำหรับ MVP ของส่วนนี้

## 7. ความสัมพันธ์กับระบบมือถือ

| ส่วน | มือถือ | เดสก์ท็อป |
|------|--------|----------|
| บันทึกรายการเร็ว | หลัก | รอง |
| Quick Capture คำสั้น ๆ | หลัก | มีได้ |
| ดูยอดสรุป | มี | ละเอียดกว่า |
| แก้ไขหลายรายการพร้อมกัน | จำกัด | ถนัด |
| ส่งออกรายงาน / เบิกงบ | พื้นฐาน | หลัก |
| มุมมองตาราง (Grid) | ไม่เหมาะ | หลัก |
| ปฏิทิน | มี | กว้างและละเอียดกว่า |

ข้อมูลซิงค์ผ่าน Supabase → บันทึกจากมือถือ แล้วมาจัดการรายงานบนเดสก์ท็อปได้เลย

## 8. เทคโนโลยีที่แนะนำสำหรับ Desktop

| ทางเลือก | ข้อดี | เหมาะเมื่อ |
|---------|------|----------|
| **Web App (Next.js / React)** | พัฒนาเร็ว, ใช้บนเบราว์เซอร์, แชร์ลิงก์ได้ | แนะนำเป็นหลัก |
| Electron | รู้สึกเป็นโปรแกรมติดตั้ง | ถ้าต้องการ offline แรงบนเดสก์ท็อป |
| ใช้ร่วมกับมือถือ (Responsive) | codebase เดียว | ถ้า UI ไม่ซับซ้อนมาก |

**แนะนำ:** ทำเป็น **Web Dashboard** ก่อน (Next.js + Supabase)  
เพราะนักบัญชีและคนทำงานมักเปิดจากคอมพิวเตอร์อยู่แล้ว และส่งออกรายงานง่าย

## 9. ลำดับความสำคัญ (เสนอ)

### Phase A — พื้นฐาน (หลัง Mobile MVP)
- หน้า List + Filter ช่วงวันที่
- สรุปตัวเลขด้านบน
- ส่งออก CSV

### Phase B — มุมมองหลากหลาย
- Grid view แบบตาราง
- Calendar view บนเดสก์ท็อป
- สถานะเบิกงบ (reimbursement_status)

### Phase C — รายงานมืออาชีพ
- แม่แบบรายงานเบิกงบ PDF
- กราฟสรุป
- เลือกหลายรายการ + bulk action

## 10. สรุป

| หัวข้อ | รายละเอียด |
|--------|-----------|
| แพลตฟอร์ม | เดสก์ท็อป / เว็บ (แนะนำ Web ก่อน) |
| ผู้ใช้เป้าหมาย | คนทำงาน, นักบัญชี, คนเบิกงบ |
| มุมมองหลัก | ปฏิทิน, ตาราง (Grid), ลิสต์, แดชบอร์ด |

| ข้อมูล | ใช้ชุดเดียวกับมือถือ (Supabase) |
| ขยาย DB | เพิ่มฟิลด์ reimbursement ใน transactions |
