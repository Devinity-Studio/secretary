# Design Document — MyDesk (Mobile)

## 1. Product Design Principles

- **Speed over completeness**: บันทึกก่อน รายละเอียดทีหลัง
- **Short command first**: Input หลักคือช่องพิมพ์คำสั้น ๆ
- **Progressive disclosure**: แสดงฟอร์มเต็มเฉพาะตอนแก้ไข
- **One record model**: ใช้โครงสร้างข้อมูลเดียวกันสำหรับเงิน / งาน / โน้ต / นัด / เป้าหมาย
- **Glanceable daily view**: หน้าแรกต้องเห็นทั้งเงินและกิจกรรมวันนี้
- **Goal with progress**: เป้าหมายการออม/วัตถุประสงค์มีระยะเวลา + ติดตามความคืบหน้าแบบเรียลไทม์

## 2. Information Architecture

### หน้าหลัก (Tab Bar)

| Tab | ชื่อ | หน้าที่ |
|-----|------|--------|
| 1 | วันนี้ / Home | สรุปวันนี้ + Quick Input + รายการล่าสุด |
| 2 | การเงิน | รายรับ-รายจ่าย, บัญชี, สรุปเดือน |
| 3 | บันทึก | Journal / Notes / Tasks |
| 4 | ปฏิทิน | ดูตามวัน/สัปดาห์/เดือน |
| 5 | ฉัน | ตั้งค่า, บัญชีผู้ใช้, ซิงค์ |

### Flow หลัก: Quick Capture

```
ผู้ใช้เปิดแอพ
    ↓
โฟกัสที่ช่องพิมพ์ทันที (หรือกดปุ่ม +)
    ↓
พิมพ์คำสั้น ๆ เช่น "กาแฟ 65" / "นัดหมอ พรุ่งนี้ 10:00"
    ↓
ระบบ parse → แสดง preview การ์ด
    ↓
ผู้ใช้กดยืนยัน (หรือแก้เล็กน้อย) → บันทึกเสร็จ
```

## 3. Key Screens (MVP)

### 3.1 Home / วันนี้
- ช่อง Quick Input ด้านบน (ใหญ่ ชัด)
- สรุปวันนี้: รายรับ | รายจ่าย | คงเหลือสุทธิ
- รายการวันนี้ (เงิน + งาน + โน้ต) เรียงตามเวลา
- ปุ่มลัดหมวดที่ใช้บ่อย

### 3.2 Quick Input / Capture Sheet
- Text input + ปุ่มไมค์ (voice ทีหลัง)
- Preview ผล parse แบบการ์ด
- ปุ่มยืนยัน / แก้ไข / ยกเลิก
- ตัวอย่างคำแนะนำด้านล่าง

### 3.3 Finance Screen
- สรุปตามช่วงเวลาที่เลือก: **รายวัน / รายสัปดาห์ / รายเดือน / รายปี**
- แท็บ: ทั้งหมด | รายรับ | รายจ่าย | โอน | ออม
- รายการเดินบัญชี + ค้นหา + กรอง
- รองรับหลายบัญชีส่วนตัว: **เงินสด, ธนาคาร (หลายบัญชี), บัตรเครดิต, e-Wallet**
- เลือกดูเฉพาะบัญชี หรือทุกบัญชี
- ปุ่มเพิ่มรายการ / โอนเงิน

### 3.4 Journal / Notes Screen
- Timeline บันทึกประจำวัน
- Task list (ยังไม่เสร็จ)
- สร้างโน้ต / งาน ใหม่

### 3.5 Calendar Screen

**มุมมองหลัก:** Month / Week / Day

**สิ่งที่แสดงบนปฏิทินได้ (เลือกเปิด-ปิดได้):**
- วันหยุดประจำสัปดาห์ (เสาร์–อาทิตย์) — ไฮไลต์สีอ่อนถาวร
- วันหยุดประจำปี (สงกรานต์, ปีใหม่, วันแรงงาน ฯลฯ)
- วันลา (ลาป่วย, ลากิจ, ลาพักร้อน)
- นัดหมาย / อีเวนต์
- บันทึก / โน้ต
- ช่วงเป้าหมาย (Goal span)
- รายการการเงินของวันนั้น (optional)

**การแสดงผลเมื่อมีหลายเหตุการณ์ในวันเดียวกัน:**
- แสดงจุดสีหรือแถบสีหลายอันตามประเภท
- ถ้าทับซ้อนกัน → แสดงเครื่องหมายเตือน (เช่น สีส้ม / ไอคอน overlap)
- คลิกวันที่ → เปิดแผ่นรายการของวันนั้น เรียงตามเวลา พร้อมระบุว่ามีอะไรทับซ้อน

**Overlap Detection (ป้องกันงานซ้ำซ้อน):**
- ระบบตรวจจับนัดหมาย/อีเวนต์ที่เวลาซ้อนกัน
- แสดงคำเตือนตอนสร้างหรือแก้ไขถ้าชนกับรายการที่มีอยู่
- ในปฏิทินวันที่มี overlap จะมีตัวบ่งชี้ชัดเจน

**คลิก/แตะวันที่:**
- เปิดรายการทั้งหมดของวันนั้น
- อัปเดตยอด Goal contribution ได้
- เพิ่มนัดหมาย / วันลา / บันทึกได้ทันที

### 3.6 Goals / เป้าหมาย (ฟีเจอร์สำคัญ)

**แนวคิดหลัก:**  
เป้าหมายคือ “Event แบบมีระยะเวลา + ความคืบหน้า” ที่สามารถติดตามได้ทั้งบนการ์ดและบนปฏิทิน

**ตัวอย่างการใช้งานจริง:**
> ผู้ใช้ตั้ง “เก็บเงิน 5,000 บาท ใน 30 วัน เริ่มวันนี้”  
> ระบบสร้าง Goal Card ขึ้นมา  
> ปฏิทินจะไฮไลต์ทั้ง 30 วัน  
> วันที่ 1 ผู้ใช้เก็บได้ 200 → การ์ดแสดง `200 / 5,000 (4%)`  
> คลิกวันที่ในปฏิทิน → อัปเดตยอดเก็บของวันนั้นได้

**Goal Card แสดง:**
- ชื่อเป้าหมาย / วัตถุประสงค์
- ความคืบหน้าแบบตัวเลข `200 / 5,000`
- เปอร์เซ็นต์ความคืบหน้า (progress bar)
- จำนวนวันที่ผ่านไป / วันที่เหลือ
- สถานะ (กำลังทำ / สำเร็จ / หมดเวลา)

**การทำงานร่วมกับปฏิทิน:**
1. ช่วงวันที่ของ Goal ถูกไฮไลต์ทั้งช่วงบนปฏิทิน
2. แต่ละวันในเป้าหมายสามารถมี “ยอด contribution ของวันนั้น” ได้
3. เมื่อคลิกวันที่ → เปิดฟอร์มอัปเดตยอดเก็บของวันนั้น (หรือเพิ่ม contribution)
4. ยอดรวมของทุก contribution จะอัปเดตกลับไปที่ Goal Card อัตโนมัติ

**ประเภทเป้าหมายที่รองรับ:**
- เป้าหมายการออมเงิน (Savings Goal) — รวมยอดเงิน
- เป้าหมายแบบนับวันสำเร็จ (Habit) — เช่น วิ่ง 30 วัน ต้องได้อย่างน้อย 25 วัน
- เป้าหมายทั่วไป / ปริมาณ (เช่น อ่านหนังสือ 12 เล่ม)
- เป้าหมายร่วม (Shared) — เช่น ผม + แฟน เก็บเงินด้วยกัน
- สร้างคำเชิญ + ส่งข้อความเชิญ (ลิงก์ / รหัสเชิญ / แชร์ผ่าน LINE)
- รองรับกรณีทำสำเร็จก่อนกำหนด → ระบบถามว่าจะ “ทำต่อ” หรือ “ปิดเป้าหมาย”
- เมื่อบรรลุเป้าหมาย → แสดงข้อความแสดงความยินดี + ให้กำลังใจ
- สามารถผูก record ประเภท contribution, transfer, income เข้ากับ goal ได้

**Quick Capture ที่รองรับ Goal:**
- `เก็บเงิน 5000 ใน 30 วัน`
- `เป้าหมาย ออมบ้าน 100000 6 เดือน`
- `ออมเข้าเป้า 200` (เพิ่ม contribution ให้ goal ที่กำลังทำอยู่)
- `วิ่ง 30 วัน อย่างน้อย 25 วัน`
- `วันนี้วิ่งแล้ว` / `วิ่งสำเร็จ` (บันทึกวันสำเร็จของ habit)

### 3.7 Settings
- บัญชีผู้ใช้ (Supabase Auth)
- จัดการบัญชีเงิน (account books)
- หมวดหมู่
- โหมดหนาแน่นของ UI
- ซิงค์ / สำรองข้อมูล
- ภาษา

## 4. UI / UX Guidelines

### Visual
- สไตล์: เรียบ, สะอาด, เน้นตัวเลขและความชัดเจน
- สีหลัก: เขียวอ่อนสำหรับรายรับ, แดง/ส้มสำหรับรายจ่าย, น้ำเงินสำหรับงาน/นัด
- Typography: ตัวเลขเงินใช้ font ที่อ่านง่ายและใหญ่พอ
- Spacing: รองรับมือถือขนาดต่าง ๆ (โดยเฉพาะมือเดียว)

### Interaction
- Quick Input ต้องเข้าถึงได้จากทุกหน้า (Floating button หรือ gesture)
- Swipe action บนรายการ: แก้ไข / ลบ / ทำเครื่องหมายเสร็จ
- Confirmation น้อยที่สุด (บันทึกทันที แล้วค่อย undo ได้)

### Density
- รองรับ 3 ระดับ: Compact / Normal / Comfortable (เก็บใน settings)

## 5. Smart Parse Design (คำสั้น ๆ)

### ตัวอย่าง Input → Output

| คำสั่งผู้ใช้ | ผลลัพธ์ที่ระบบควรเข้าใจ |
|-------------|-------------------------|
| `กาแฟ 65` | expense 65, หมวดอาหาร, วันนี้, บัญชีล่าสุด |
| `เงินเดือน 28000 กสิกร` | income 28000, หมวดเงินเดือน, บัญชีกสิกร |
| `โอนออม 5000` | transfer 5000 → บัญชีออม |
| `นัดหมอ พรุ่งนี้ 14:00` | event, พรุ่งนี้ 14:00, reminder |
| `ซื้อของ 1,200 บัตร` | expense 1200, ช้อปปิ้ง, บัตรเครดิต |
| `จ่ายค่าไฟ` | expense, หมวดสาธารณูปโภค (ถามจำนวนถ้าไม่มี) |
| `วันนี้เหนื่อยมาก` | note / journal |
| `เก็บเงิน 5000 ใน 30 วัน` | goal, target 5000, duration 30 วัน, เริ่มวันนี้ |
| `เป้าหมาย ออมบ้าน 100000 6 เดือน` | goal, target 100000, duration 6 เดือน |
| `ออมเข้าเป้า 200` | contribution 200 เข้า goal ที่กำลังทำอยู่ |

### Parse Pipeline (Logic)

1. ตรวจจับตัวเลขและประเภทเงิน
2. ตรวจจับคำสำคัญประเภท (รายรับ/รายจ่าย/โอน/นัด/งาน)
3. ตรวจจับวันที่สัมพัทธ์ (วันนี้, พรุ่งนี้, วันจันทร์...)
4. ตรวจจับบัญชีและหมวดหมู่จาก dictionary + ประวัติผู้ใช้
5. สร้าง draft record → แสดง preview ให้ผู้ใช้ยืนยัน

## 7. Data Model (สรุป)

ใช้แนวคิด **Unified Record** เหมือน architecture เดิม แล้วปรับให้เหมาะกับมือถือ + Supabase

**records**
- id, user_id
- type: `expense` | `income` | `transfer` | `task` | `event` | `note` | `journal` | `goal` | `contribution`
- title, description, content
- amount, finance_type, account_book_id, to_account_book_id
- category, tags
- start_at, end_at, all_day, reminder_at
- status (สำหรับ task / goal: active | completed | cancelled)
- parent_id (ใช้ผูก contribution → goal)
- target_amount (สำหรับ goal)
- current_amount (คำนวณหรือเก็บ cache สำหรับ goal)
- metadata (jsonb)
- created_at, updated_at, deleted_at

**account_books**
- id, user_id, name, type, color, icon, target_amount...

**categories**
- id, user_id, name, type, icon, color

**settings**
- key-value ต่อ user

### Goal เฉพาะ (รายละเอียด)

**Record ประเภท `goal`**
- `type = 'goal'`
- `title` = ชื่อเป้าหมาย (เช่น “เก็บเงินซื้อของ”)
- `target_amount` = ยอดเป้าหมาย (5000)
- `current_amount` = ยอดรวมที่เก็บได้จริง (คำนวณจาก contribution หรือ cache)
- `start_at` + `end_at` = ช่วงเวลาของเป้าหมาย
- `status` = `active` | `completed` | `cancelled` | `expired`
- `metadata` สามารถเก็บ unit (บาท, ครั้ง, เล่ม ฯลฯ) และประเภทเป้าหมาย

**Record ประเภท `contribution`**
- `type = 'contribution'`
- `parent_id` = id ของ goal
- `amount` = ยอดที่เก็บได้ในวันนั้น
- `start_at` = วันที่ของ contribution (สำคัญมากสำหรับการแสดงบนปฏิทิน)
- ใช้สำหรับบันทึกยอดรายวันของเป้าหมาย

**การคำนวณความคืบหน้า**
```
current_amount = SUM(amount ของ contribution ทั้งหมดที่ parent_id = goal.id และยังไม่ถูกลบ)
progress_percent = (current_amount / target_amount) * 100
```

**Calendar Highlight & Daily Update**
- วันที่อยู่ระหว่าง `start_at` ถึง `end_at` ของ goal ที่ยัง `active` จะถูกไฮไลต์ทั้งช่วง
- สีไฮไลต์แตกต่างจาก event ปกติ (แนะนำสีม่วงอ่อนหรือเขียวอ่อน)
- เมื่อมี contribution ในวันนั้น → แสดงตัวเลขยอดของวันนั้นบนช่องวันที่
- **การคลิกวันที่ในปฏิทิน**:
  1. ระบบตรวจว่าวันที่นั้นอยู่ในช่วง goal ใดบ้าง
  2. เปิดแผ่น (bottom sheet / modal) ให้เพิ่มหรือแก้ไขยอด contribution ของวันนั้น
  3. บันทึกแล้ว Goal Card อัปเดตทันที

## 8. Security & Privacy

- ใช้ Supabase Row Level Security (RLS) บังคับว่า user เห็นได้แค่ข้อมูลตัวเอง
- ข้อมูลสำคัญเข้ารหัสตอน rest ถ้าระดับสูง (optional)
- ไม่เก็บข้อมูลการเงินไปใช้วิเคราะห์ภายนอกโดยไม่ได้รับอนุญาต
- รองรับการ Export ข้อมูลทั้งหมด + ลบบัญชี
